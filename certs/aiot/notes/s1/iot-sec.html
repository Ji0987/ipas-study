AIoT 設備數量多、分布廣、常無人看管又不易更新，攻擊面比一般資訊系統大。資安知識可分為密碼學基礎、裝置與通訊安全、平台安全、資料安全、軟體安全與隱私保護。

密碼學工具

工具做什麼演算法／例子
對稱式加密雙方用同一把金鑰加解密，速度快，用來加密傳輸資料AES、DES、Twofish；WPA-PSK 也是共用金鑰
金鑰交換安全地交換、更新對稱金鑰Diffie-Hellman（DHE）、ECDH
非對稱式加密公鑰與私鑰成對，一把加密只有另一把能解RSA、ECC；運算量大，感測器通常不用
雜湊（Hash）單向不可逆，驗證完整性、儲存密碼與 API 金鑰；計算量小SHA-256、SHA-512、SHA-3（比特幣用 SHA-256）
數位簽章用發送者私鑰簽署、公鑰驗證，提供不可否認性與完整性RSA、ECDSA
💡
公私鑰怎麼用：要保密給 B → 用 B 的公鑰加密，B 用私鑰解；要證明是 A 發的 → A 用自己的私鑰簽，大家用 A 的公鑰驗證。單獨使用雜湊只能保護完整性，不能保護機密性。

依設備能力選擇機制：感測器節點算力低，可用明文或 預先共用金鑰（PSK）加密；閘道器與電腦算力較高，可用 TLS、X.509 憑證、mTLS 等更安全的方式。

資安三要素與 AAA

CIA
  • 機密性：只有授權者能取得（加密、驗證、遮罩、存取控制）
  • 完整性：資料未被竄改（雜湊、訊息鑑別碼 MAC）
  • 可用性：服務持續可用（SLA、負載平衡）；會被 DDoS、SYN Flood 破壞
AAA
  • 認證（Authentication）：確認你是誰
  • 授權（Authorization）：你可以做什麼
  • 稽核（Auditing／Accounting）：事後追查誰在何時做了什麼

SLA 99% 約等於每月停機 7.2 小時，99.99% 約 4.3 分鐘。

常見攻擊

攻擊手法
DoS／DDoS大量請求耗盡資源使服務中斷；DDoS 由殭屍網路多台同時發動（如 Mirai 控制大量攝影機、路由器）。手法有 SYN Flood、UDP Flood、DNS 放大攻擊
中間人攻擊（MITM）介入通訊雙方，攔截、竄改後再轉送
重送攻擊（Replay）把攔截到的合法封包重複或延遲送出（如重送開門指令）
暴力破解、預設密碼設備沿用預設帳密或弱密碼，被自動化工具入侵
竊聽、竄改無線訊號在空中可被任何人接收
實體入侵從電路板的 JTAG／UART／Console 取得管理權限；量產前應關閉這些介面
韌體漏洞設備難更新，已知漏洞可存在數年（N-day 攻擊）

防護措施

  • 裝置：更換預設密碼、使用強密碼、最小權限、定期更新韌體（OTA 搭配韌體簽章 Secure Boot 與加密）。
  • 通訊：依設備能力選 PSK、API Key、Token、mTLS、X.509 認證；傳輸用 TLS/SSL 加密，並可加 MAC 或簽章。IPv6 內建 IPSec（AH 驗證、ESP 加密）。
  • 網路隔離：以 VLAN、防火牆、不同 SSID 把 IoT 裝置與一般網路切開，遭入侵時阻斷橫向攻擊（中繼器沒有隔離作用）。
  • 平台：防火牆白名單（Layer 2／3，限定來源 IP 與埠號）；進階用 WAF（網頁應用程式防火牆，擋 SQL Injection、XSS、Bot）。
  • 資料：存取控制、加密、遮罩、完整性保護、備份與災難復原（DR）。RPO＝可能遺失多少時間的資料（一天備份一次 RPO 就是 24 小時）；RTO＝多久能恢復服務。
  • 軟體（SDLC）：源碼掃描（靜態分析）、函式庫掃描、黑箱掃描、滲透測試（上線前與定期）。
  • 認證方式：生物特徵（指紋、靜脈、虹膜）難偽造；密碼是較弱的一種。

隱私保護

原則做法
去識別化／匿名化遮罩或轉成匿名編號，無法追溯到個人（邊緣端先去識別化再上傳）
資料極小化只收集必要的資料，例如門禁只記進出時間、不存整段影像
使用者同意告知並取得同意才收集；提供資料可攜與刪除的權利
目的限制與動態同意告知用途；挪作他用（如送進 AI 分析）要再次取得同意

個人身分識別資料依個資法不能任意自動蒐集。蒐集歐盟使用者資料須遵守 GDPR。設計時採用「由設計起始的隱私（Privacy by Design）」。
