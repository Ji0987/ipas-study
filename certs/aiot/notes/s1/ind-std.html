工業 4.0 要求產線設備聯網、資料數位化。早期產線多用簡單可靠的 Modbus，但它沒有加密與身分驗證；現代工廠轉向內建資安機制、可跨廠牌互通的 OPC UA。

封裝與解封裝

工業網路常以五層模型（應用、傳輸、網際網路、資料連結、實體）說明。傳送端每往下一層就加上該層標頭（封裝），接收端逐層移除（解封裝）。以 Modbus 為例：指令先變成 PDU（功能碼＋資料），Modbus TCP 再加 MBAP 標頭交給 TCP/IP；Modbus RTU／ASCII 則加上裝置位址與 CRC／LRC 校驗碼，經 RS-232／RS-485 傳送。

OPC UA（開放平台通訊統一架構）

由 OPC 基金會制定的跨平台、開放、統一的工業通訊標準，是工業 4.0 的關鍵標準之一，對應 OSI 的第 7 層（應用層）。

獨立性：不綁作業系統與硬體（跨平台） 安全性：認證、授權、完整性、加密 擴展性：可自訂服務與資訊模型 多語言實作：C++、C#、Java、Python
  • Client／Server 架構：Server 在設備端，收集控制器與感測器資料並轉成標準格式；Client 向 Server 要資料。
  • 設備聯網閘道器：把各廠牌的存取函式庫封裝在 OPC UA Server 中，對外提供統一存取方式；AI 系統透過閘道器讀取轉換後的 OPC UA 資料，不直接讀 PLC 原始訊號。
  • 資訊模型：以節點描述設備資料，NodeID 在資訊模型中不可重複。
  • 讓設備、MES、ERP 之間的資料水平與垂直整合，支援預測性維護與製程優化。
資料存取方式運作例子
讀／寫（Read/Write）Client 主動讀取或寫入變數讀產品重量、寫入新的轉速與進給率

MTConnect（機械工具連接協定）

專為工具機資料交換制定的開放標準（免權利金），定義標準的設備參數名稱。特點：唯讀（只讀取設備資料，不寫入指令）、資料以 XML 表示、以 HTTP 傳輸，具可擴展性、互操作性、可讀性，可讀取機台參數。

Modbus

工業領域最常見的簡單協定，用於 PLC、溫控器、伺服驅動器。主從（Master/Slave、Client/Server）架構，不支援加密與身分驗證，在不受信任的網路中容易被監聽、竄改。

其他工業介面與設備

  • IO-Link（IEC 61131-9）：點對點串列通訊，連接感測器、致動器與控制器，最長 20 公尺，支援參數設定與診斷；速率低，只傳製程資料，不傳大型檔案。
  • PLC（可程式邏輯控制器）：高即時性、抗干擾、長期穩定，負責控制製程設備；單晶片微控制器較便宜、彈性高。
  • RESTful API：以 URI 識別資源，用 HTTP 方法做 CRUD（GET 讀、POST 建、PUT 改、DELETE 刪），客戶端與伺服器端分離，常用於系統串接。
  • MQTT：發布者、訂閱者、Broker 三角色，發布與訂閱完全解耦；Keep Alive、遺囑（LWT）、TLS 與 QoS 見 中介軟體與平台。
