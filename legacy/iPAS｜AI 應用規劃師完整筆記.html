3.1人工智慧概念
AI 定義、功能分類與技術底層架構AI 概念
▾

AI 定義

人工智慧（AI）是一種模擬人類智慧的技術，使機器能執行需人類智慧才能完成的任務，如學習、推理、解決問題、感知環境等。近十年來隨著算力提升、開放資料普及、演算法精進而快速發展。

依功能分類

類型說明應用例
分析型 AI洞悉數據模式，處理大量數據提供見解商業智慧、資料分析
預測型 AI基於歷史資料預測未來趨勢和行為市場預測、風險評估
生成型 AI根據使用者 prompt 生成文字、語音、圖像、影片ChatGPT、DALL-E、Midjourney

AI 技術底層架構

層次說明
演算法AI 邏輯基石；迴歸分析、分類、決策樹、基因演算法
機器學習（ML）資料訓練模型進行預測/分類；監督/非監督/強化式學習
深度學習（DL）人工神經網路；語音辨識、影像、NLP；框架：TensorFlow、PyTorch
專家系統基於規則與知識庫，模擬人類專家決策；醫療診斷、財務分析

AI 企業應用目標

提高效率增強決策能力 提供個人化服務促進創新

各行業 AI 應用場景

行業應用例
醫療保健疾病診斷（分析 X 光/MRI）、藥物研發、個人化醫療
金融風險評估、欺詐檢測、自動交易
製造業自動化生產、品質控制（影像辨識）、預測性維護
交通自動駕駛、交通流量預測
娛樂遊戲開發、虛擬現實、內容推薦
AI 治理概念（AI Governance）治理
▾

AI 治理是確保 AI 系統以負責任、透明且符合倫理的方式開發和使用的框架，旨在平衡技術創新與社會風險。

AI 治理核心要素

透明性：模型決策過程可解釋 公平性：避免歧視性輸出 問責性：明確責任歸屬 安全性：防止惡意使用 隱私保護：符合個資法規

國際 AI 治理框架

框架說明
歐盟 AI 法案依風險分級管理，禁止高風險 AI 用途
UNESCO 建議書2021年，強調 AI 人道主義原則
台灣 AI 基本法2026年1月施行，推動負責任AI發展
⏱️ 法規資訊截至 2026 年初整理。AI 相關法規更新頻繁（如台灣 AI 基本法 2026/1 生效），實際應考與應用請以主管機關最新公告為準。
⚠️
AI 治理 ≠ 限制 AI，而是確保 AI 發展可持續、可信任、對社會有益
3.2資料處理與分析概念
資料類型與蒐集方式資料
▾

三種資料結構類型

類型說明範例
結構化資料清晰固定結構，行列形式，易查詢MySQL、Excel 表格
半結構化資料有標籤但格式靈活，層次化描述XML、JSON、CSV
非結構化資料無固定結構，需處理後才能分析圖片、影像、音訊、電子郵件

常見資料蒐集方法

方法說明
問卷與調查線上或線下收集第一手數據，用於市場研究、用戶回饋
自有產品數據企業自有網站、App、智慧裝置（手錶、汽車）的互動數據
外部公開數據政府資料開放平台 API、網路爬蟲（Scrapy）
外部付費數據向第三方購買，補充內部數據（市調數據、人口統計）
網路爬蟲抓取公開網站數據（商品價格、評論、新聞）
資料清洗、轉換與整理資料
▾

資料清洗（Data Cleaning）四大問題

問題類型說明處理方式
遺缺值（Missing Value）某些欄位沒有記錄有效數據填補（均值/中位數/眾數/插補法）或刪除記錄
重複值（Duplicate）相同內容的記錄重複出現識別重複項→保留一份→刪除其他
錯誤值（Error/Invalid）值不符合合理範圍或明顯錯誤檢測並修正（如年齡=-5、Taiwan→Taiwwn）
離群值（Outlier）遠離大多數數據點的異常值根據業務需求決定：保留、修正或刪除

資料轉換（Data Transformation）

技術說明
格式轉換CSV → JSON、PDF → 文字等格式互換
類型轉換字串 → 數值，類別 → 數字編碼
正規化/標準化縮放到 [0,1] 或標準差 1，消除單位影響
資料離散化連續型數據轉為離散類別（年齡分「青年/中年/老年」）
💡
資料前處理品質直接影響模型準確性：Garbage In, Garbage Out（垃圾進，垃圾出）
資料隱私、安全與倫理隱私
▾

資料隱私核心概念

PII（個人識別資訊）：直接識別個人 匿名化：移除識別資訊 假名化：以代碼替換真實識別 差分隱私：加入統計雜訊

資料生命週期

① 蒐集② 儲存③ 處理 ④ 分析⑤ 共享⑥ 刪除/銷毀

主要資料保護法規

法規適用重點
GDPR歐盟含刪除權/遺忘權（第17條），最嚴格
CCPA美國加州消費者有權知道資料用途、拒絕出售
台灣個資法台灣個人資料蒐集、處理、利用的規範
⏱️ 法規資訊截至 2026 年初整理。AI 相關法規更新頻繁（如台灣 AI 基本法 2026/1 生效），實際應考與應用請以主管機關最新公告為準。

AI 倫理議題

  • 演算法偏見：訓練數據存在偏頗 → 模型輸出歧視性結果
  • 深偽（Deepfake）：生成式 AI 製造假影片、假音訊
  • 著作權爭議：AI 生成內容的版權歸屬問題
3.3機器學習概念
機器學習原理與三大學習類型ML
▾

機器學習定義

機器學習（ML）是一種資料驅動的方法，讓計算機系統從經驗中學習、建立模型並自動執行任務，無需依賴人為編寫的規則。透過數據發現規律，實現分類、迴歸、聚類及決策。

機器學習三大類型

類型資料需求學習方式典型應用
監督式學習有標記的數據學習輸入→輸出映射關係分類（郵件過濾）、迴歸（房價預測）
非監督式學習無標記的數據探索資料內在結構聚類（客戶分群）、降維（PCA）
強化學習環境回饋（獎勵/懲罰）試錯學習最優策略遊戲 AI（AlphaGo）、機器人控制、自駕車
💡
面試高頻：自動駕駛、圍棋 AI → 強化學習（序列決策 + 試錯學習）

機器學習技術優勢與挑戰

優勢
  • 自適應能力：可動態更新
  • 處理大規模結構化/非結構化資料
  • 可擴展性高
挑戰
  • 資料品質不均衡
  • 模型解釋性不足
  • 偏見數據導致歧視性輸出
常見機器學習模型ML 模型
▾
模型核心原理應用場景
邏輯迴歸Sigmoid 函數輸出 0–1 機率，最大似然估計學習參數醫療診斷、行銷轉換率、金融風險
支援向量機（SVM）最大化類別間距的超平面，核函數處理非線性文本分類、圖像識別、生物資訊
決策樹資訊增益/吉尼係數遞迴分割，形成樹形規則醫療診斷、金融風險、行銷分析
隨機森林多棵決策樹 Bagging，取投票/平均，降低過擬合醫學影像分類、金融市場分析
神經網路多層神經元，反向傳播調整權重，學習深層特徵語音辨識、自動駕駛、圖像辨識
💡
隨機森林 = 多棵決策樹的集成（Bagging），可有效降低單一決策樹的過擬合風險
3.4鑑別式 AI 與生成式 AI 概念
鑑別式 AI vs 生成式 AI（高頻考點）核心
▾
鑑別式 AI（Discriminative AI）
  • 學習 P(y|x)：條件概率
  • 找到類別間的「分類邊界」
  • 目標：分類、預測、識別
  • 代表：SVM、邏輯迴歸、神經網路、決策樹
  • 優勢：標記數據充足時準確性高
生成式 AI（Generative AI）
  • 學習 P(x,y) 或 P(x)：聯合/邊際分佈
  • 模擬真實資料分佈，創造新樣本
  • 目標：生成新內容
  • 代表：GAN、VAE、Diffusion、GPT
  • 優勢：創新內容生成能力強

生成式 AI 主要技術

技術原理應用
GAN（生成對抗網路）生成器 vs 鑑別器相互博弈高品質圖像生成、風格轉換
VAE（變分自編碼器）編碼→潛在空間→解碼，機率生成穩定生成、數據擴增
Diffusion Model（擴散模型）從雜訊逐步還原清晰數據Stable Diffusion、DALL-E 3
Transformer / LLMSelf-Attention，大規模預訓練GPT 系列、BERT、文字生成

鑑別式 + 生成式整合應用

  • 醫療：生成式 AI 增補稀缺醫學影像 → 鑑別式 AI 進行診斷分類
  • 金融：生成式 AI 生成市場情境 → 鑑別式 AI 進行風險評估
💡
關鍵差異：生成式 AI 的同一輸入可產生不同輸出（固有變異性）；鑑別式 AI 輸出確定性更高

3.1No Code / Low Code 概念
No Code / Low Code 概念與生成式AI整合NoCode
▾

定義

No Code / Low Code 平台是推動 AI 民主化的重要力量，使非技術背景人員也能創建和部署 AI 應用，打破軟體工程師壟斷開發的關卡。

No Code vs Low Code 比較

No Code（無代碼）
  • 視覺化介面 + 拖放操作
  • 零程式碼技術需求
  • 適合：非技術背景者、快速原型、小型應用
  • 限制：複雜邏輯難以實現
Low Code（低代碼）
  • 視覺化工具 + 少量程式碼
  • 需具備一定技術背景
  • 適合：中大型企業、複雜邏輯應用
  • 保留程式設計靈活性

生成式 AI 如何強化 No/Low Code

  • 自動生成程式碼（減少開發時間）
  • 模板設計優化（AI 提供介面設計建議）
  • 數據分析與決策（AI 基於專案數據提供建議）
  • AI 驅動的 UI/UX 設計（文字 → UI 設計方案）
  • 自動化行銷文案生成
  • 個人化 App 快速開發
ℹ️
代表工具：Bubble（No Code 網頁）、Webflow（No Code 設計）、Power Apps（Low Code）、AppSheet（Google No Code）
No Code / Low Code 平台評估 6 大因素評估
▾
#因素說明
①目標用戶與技術需求No Code 面向非技術者；Low Code 面向有技術背景者
②功能與擴展性系統整合能力（CRM、ERP）；高度自訂性
③安全性與合規性資料加密、身份驗證、符合資料保護法規
④成本與效益TCO（總擁有成本）；ROI（投資回報率）
⑤技術支援與社群資源技術文件、線上論壇、專業客服、社群活躍度
⑥市場評價與案例用戶評價；相似行業成功案例
💡
TCO = Total Cost of Ownership（購買+維護+培訓）；ROI = Return On Investment（投資回報率）
3.2生成式 AI 應用領域與工具使用
生成式 AI 技術架構與特點技術
▾

生成式 AI 在 2022 年 11 月 ChatGPT 推出後掀起科技革命，廣泛改變各行業工作型態。

技術架構三大基礎

技術說明
深度學習網路多層神經網路特徵提取；自注意力機制（Self-Attention）處理長距離依賴
訓練數據處理資料清洗（去噪/填補）；標記化（Tokenization）；向量化（Vectorization）
推理機制溫度參數（低→保守，高→創意）；Top-k 採樣；Nucleus 採樣

AI 幻覺（AI Hallucination）

⚠️
AI 幻覺：模型生成看似合理但實際錯誤的資訊。成因：訓練數據限制、過度自信。防範：RLHF（人類回饋強化學習）、RAG（檢索增強生成）、事實核查

關鍵技術術語

RLHF：人類回饋強化學習，讓生成結果更符合人類期望 RAG：檢索增強生成，結合外部知識庫減少幻覺 Fine-tuning：微調，在特定領域數據上進一步訓練 LLM：大型語言模型（如 GPT-4、Gemini）
常見生成式 AI 工具與提示工程工具
▾

常見工具分類

類型代表工具用途
文字生成ChatGPT（OpenAI）、Gemini（Google）、Copilot（Microsoft）對話、寫作、程式碼、分析
圖像生成DALL-E（OpenAI）、Midjourney、Stable Diffusion藝術創作、產品設計、廣告素材
影片/音訊Sora（OpenAI）、ElevenLabs（語音）影片生成、語音合成
程式碼GitHub Copilot、Cursor程式碼補全、生成、除錯
多模態GPT-4V、Gemini Ultra文字+圖像混合輸入/輸出

提示工程（Prompt Engineering）

透過精心設計輸入提示（Prompt）來引導 AI 產生更好輸出的技術。

技巧說明
角色設定「你是一位資深醫師，請回答…」
具體指令明確說明格式、長度、語氣要求
提供例子Few-shot：給出幾個範例讓 AI 仿照
思維鏈Chain-of-Thought：「請一步一步分析…」提升推理準確度

使用生成式 AI 的注意事項

  • 版權與合法性：生成內容可能涉及版權問題

▾
